### D-19（P0 · 可用性致命）· `.field` 命名冲突 → 输入框与眼睛**纵向堆叠**
- 客户原话：「我每一次看到时不知道'主密码'要在哪里输入……我首先看到的是'至少 8 位'那几个大字，我以为要在他下面某个地方输入，可是没有找到。」
- 命中：`src/components/CreateVaultWizard.svelte:133`、`src/components/LockScreen.svelte:106`
- **机制（关键）**：`global.css:118` 有 `.field { display:flex; flex-direction:column; gap:.35rem; margin-bottom:.75rem }`；两个组件各自又定义了**同名局部** `.field { display:flex; align-items:center; border:...; padding-right:.25rem }`。
  Svelte 局部样式带 hash → 特异性 0,2,0 > 全局 0,1,0，所以 `display`、`align-items` 由局部胜出；
  **但 `flex-direction: column` 只存在于全局规则里、局部没覆盖它 → 直接漏过来**，
  于是输入框与眼睛按钮**竖着摞**，外面套一层边框，看起来就是个又高又怪的大框。
- 旁证：下面「确认主密码」没包在 `.field` 里，高度正常 —— 两个框长得不一样，正是这个 bug 的指纹。

### D-20（P0 · 语义反了）· 密码可见性图标方向错

## D-40 跟进：手机粘贴配对报「文件读写错误」（23:20）

- **文案陷阱锤定**：`From<std::io::Error> → CoreError::Io("io:<kind>")`，TCP 同步链路的 TimedOut/ConnectionRefused/Reset 与真文件 IO 全被折叠成 `err.io`「文件读写出错」。主人所见大概率是**网络错误**而非文件错误。
- **关键证据**：transport::connect 失败映射 SyncAborted（「同步已中止」）——主人见到 err.io 说明 **TCP 已连上**，挂在帧交换阶段（最可能 io:TimedOut：30s 内没等到对端握手响应）。
- **修复**：`CoreError::message_key()` 按 io kind 细分——TimedOut→err.network_timeout / ConnectionRefused→err.network_refused / Reset|BrokenPipe→err.network_broken / 其余（含两可的 UnexpectedEof）→err.io 兜底。i18n 三语齐加（zh/en parity）。**下次重试时三种新文案直接分流根因**。
- **已排查排除**：路径（app_data_dir，建库成功=可写）、Host 轮询线程生命周期（独立线程 200ms 轮询，与页面无关）、无 unwrap 崩点、Reject 都有帧、TTL=120s（过期有专门文案）。真机重试后按新文案再定位。

## D-41 手机状态栏压顶栏、汉堡点不到（23:15）

- **根因（锤死）**：Tauri 模板生成的 `MainActivity.kt` 显式 `enableEdgeToEdge()` → WebView 铺满全屏；wry 0.57 Kotlin 层**零 insets 处理**（grep 0 命中）→ 系统状态栏（时间/电量）浮在前端顶栏上，汉堡热区被抢。客户真机截图：状态栏「23:04」与 ☰ 重叠。
