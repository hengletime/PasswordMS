# PasswordMS 1.6.1

这一版最要紧的一件事：两台机器里存的不是同一个保险库时，**配对会当场告诉你**，而不是等你点「立即同步」之后，一台报「文件读写错误」、另一台报「加密操作失败」。

## 配对说成功，同步却两头报错

现象：笔记本和台式机各自都有数据，先配对（界面显示成功），再点「立即同步」——笔记本提示「文件读写错误」，台式机提示「加密操作失败」。两条提示看起来像两个毛病，其实是一件事的两面：合并数据的那一端，用本机的保险库密钥解不开对方发来的条目，于是中止、断开连接；发起的那一端只是被掐断了连接，所以只能给一句笼统的读写错误。

根子在配对那一步。判断「这两台是不是同一个保险库」时，程序看的是「本机上有没有和对方的配对记录」。可记录比密钥活得久：中途重装过、或者从备份恢复过别的库，记录还在，密钥早换了，这句话依然成立——于是配对悄悄放行，问题被推到同步时才炸，而且炸出来的提示和真正的原因毫无关系。

现在改成只认一件事：**两端的保险库密钥是不是同一把**。不是，配对当场停下，并且说清楚：这两台设备里的数据不是同一个保险库，对方的保险库密钥已经变了（重装过，或恢复过别的库），配对不能继续。后面直接给下一步——留一台为准，在那一台上「导出保险库」，到另一台「从备份恢复」，然后再重新配对。

已经配好对、正在踩这个坑的两台机器也不用先解绑：直接点「立即同步」，合并的那一端会给出同一句话和同样的下一步，不再只丢一句「加密操作失败」。

## 没被改坏的部分

- 同一台机器重复扫码配对、解绑之后重新扫码配对，都照旧一次通过——判断标准从「有没有记录」收紧到「密钥是否相同」，这两种情况密钥本来就相同，不受影响。
- 两台**真正**同一个保险库之间的同步、冲突箱、删除传播、附件传输，一条逻辑都没动。
- 本版不碰任何加密算法、不改容器格式，不需要迁移数据。
- 「本机保险库非空，无法直接采用对端密钥」这条提示仍然单独存在：它说的是「还没有这一组的历史，但本机库里有东西」，和本版新增的「有历史、可历史已经过期」是两件事，用户要做的事也不同。

## 已知限制

- **不做两个保险库的合并**。这是从第一版就定下的红线（U1/U2）：遇到两端数据不同源，只能选一台为准，把资料导出再恢复到另一台，程序不会替你把两库掺在一起。
- 若对端这一轮一条条目变更都没有、只有附件要传，报错仍是「加密操作失败」。配对判定收紧之后，这条路径在正常流程里走不到，但确实还没改。
- 两台机器都要升级到 1.6.1 才会看到新提示；只升一台时，旧的那台仍按老样子报「加密操作失败 / 文件读写出错」。
- Windows 便携版仍然要整个 zip 解压使用，单拷 exe 不带 WebView2 引导与图标资源。

## English summary

If two devices hold **different vaults**, pairing now refuses on the spot and says so, instead of appearing to succeed and then failing later with a misleading "file read/write error" on one side and "encryption failed" on the other. The old check only asked "have I paired with this device before?" — a record outlives the key it was made with, so a reinstall or a restore from a different backup silently produced a pairing that could never work. The check now requires that both sides share the same vault key; if not, pairing stops and tells you to keep one device as the source of truth (export the vault there, restore it on the other, then pair again). Devices already stuck in this state get the same explanation the moment they hit "Sync now" — no need to unpair first. Re-pairing the same vault (repeated scan, or after unpairing) still works exactly as before. Two vaults are still never merged, by design.
