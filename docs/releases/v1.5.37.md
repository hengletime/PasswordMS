# PasswordMS 1.5.37

这一版没有新功能，改的全是「退路」：本机备份和外部导出。三条问题都指向同一件事——
备份系统的存在意义是"出事时还有一份能用的"，所以凡是会让备份自己停摆、或者悄悄删掉
用户明确要留的那一份的地方，都得先修掉。

## 备份不再因为「库变小了」而停摆

配额原来是 `当前库体积 × 12`（封顶 1 GB）。库是会变小的：删掉大量条目，或者从一份
很旧的备份恢复回来。库一缩，配额立刻塌到盘上既有备份之下，于是每一次新备份都被拒绝，
而界面只能显示一句失败——上一版给了它一个「知道了」，但那只是让失败说得清楚，
备份本身仍然没恢复。

现在配额的基数取「当前库体积」与「盘上最大一份备份」两者的大者：库缩水不再连带砍配额。
真正的约束还在——槽位轮转把份数压在十来份，库大到几十兆以上仍会撞上 1 GB 封顶，
用户钉住很多份时配额也仍会挡住。

## 钉住的备份不会被配额腾挪删掉

「钉住」是用户对某一份明确表态「这个我要留着」。轮转早就绕开了它，但配额不足时
腾地方的那条路没读这份名单——配额一紧，钉住的照样被删，而界面上「已钉住」还亮着。
现在两条路读同一份名单：宁可这一次不备份，也不动用户点过「留下」的那一份。

## 导出不会先毁掉上一份外部副本

导出对话框的默认文件名每次都是同一个，绝大多数人就是点「保存」覆盖上一次那份。
旧实现是先截断目标再灌数据——中途拔盘、空间不足、进程被杀，旧副本没了、新的也不完整。
而「导出」恰恰是换机、卸载、重装前的那一步。现在改成同目录临时文件 → 校验长度 →
落盘 → 改名覆盖：要么是新的一份，要么还是旧的那一份，没有第三种状态。

## 已知限制

- Android 上的导出走系统文件选择器，写的是系统给的句柄，没有"同目录临时文件"这一层；
  它靠的是写完回读长度校验（0 字节一律判失败）。
- 「外部副本只留最新一份 + 上一份」仍然是**操作约定**，程序不会去删用户自己目录里的
  旧副本。理由是删除不可逆，而默认文件名本来就每次覆盖同一份，不会越攒越多。
- 配额基数取大者之后，普通场景下配额几乎不再触发；它实际生效的两条路是「钉住的份数
  超过名额」和「库大到撞上 1 GB 封顶」。
- 恢复前快照写不出来时，仍会拦下覆盖并要求用户明确接受"没有自动回滚点"，行为未变。

## English summary

This release fixes three defects in the backup and export paths; there are no new features.

- **Backup quota no longer collapses when the vault shrinks.** The allowance used to be
  `current vault size × 12` (capped at 1 GB). After deleting many entries or restoring an
  old copy, the vault gets smaller, the allowance dropped below the backups already on
  disk, and every new backup was refused. The base is now the larger of the current vault
  size and the largest single backup on disk. The real limits remain: slot rotation keeps
  the number of copies near a dozen, a large vault still hits the 1 GB cap, and heavy
  pinning can still exhaust the allowance.
- **Pinned backups are no longer deleted to free space.** Rotation already skipped pinned
  copies, but the quota-driven trimming path never read that list. Both paths now read the
  same list: if room cannot be made without touching a pinned copy, that snapshot is
  skipped and the failure is reported instead.
- **Exporting no longer destroys the previous external copy.** The default destination is
  the same filename every time, and the old code truncated the target before copying.
  An interrupted copy left neither a valid old copy nor a valid new one. Export now writes
  a temporary file in the same directory, verifies its length, flushes it, and renames it
  over the destination.

Known limits are listed in the Chinese section above; the most relevant one is that
Android exports go through the system document picker and rely on a read-back length check
instead of a same-directory temporary file.
