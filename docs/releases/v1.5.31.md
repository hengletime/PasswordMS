# PasswordMS 1.5.31

这一版修一个「按钮明明有用，却几乎永远不出现」的问题——设置里的「用这份退回去」。

## 按钮为什么不出现

备份列表里那份「用这份退回去」，原来只认一种备份：**恢复之前自动拍的那一份**（`pre-restore`）。

而这一种备份，只有在你**已经成功做过一次「从备份恢复」之后**才会被写出来。也就是说：

> 从来没用过恢复功能的人 → 一份 `pre-restore` 都没有 → 那个按钮整块不渲染。

一个刚装好、备份目录里有好几份完整可用副本的人，界面上根本看不到退回去的入口。实测绿色版 `backups/` 里有 3 份完整可用的整库副本（改密后那一份 + `old-key/` 批次里的「压缩前」「改密前」），`pre-restore` 是 0 份。

这已经是同一个错误的第三种形态了：1.5.29 是「承诺了一个没实现的动作」，1.5.30 是「有动作，但触发条件几乎不成立」，这一版是「有几份就列几份」。

## 现在怎么列

**候选集改成「备份目录里所有整库副本」**：五类事件备份、`bak.<日期>`、`last.bak`、以及 `old-key/<批次>/` 里的每一份。名字认不出来的（用户自己丢进去的杂文件）不列——宁可少列，不可列错。

每行显示三样：**时刻 · 是哪一步之前/之后的备份 · 要不要旧密码**。

按钮和确认框跟着这份清单走：需要旧密码的那几份，确认框里问的就是「这一份备份的主密码」，并说明清楚当前密码打不开它；不需要旧密码的，问的是当前密码。成功回执也分两套，不再一句「恢复成功」糊过去。

清单里的每份备份用一个**令牌**标识（`文件名` 或 `批次目录/文件名`），**不拼路径**——拼路径就等于把文件系统的自由度交给前端，越界风险不值这个方便。

## 已知限制

- 「要不要旧密码」按**目录位置**判断（在 `old-key/` 里，或者是改密前那一份）。从 `old-key/` 里某份退回去之后，位置与事实会反过来——当前代那几份要的其实是退回去之前那个密码。敢这样留着，是因为这个入口在设置页里、必须先解锁才能进来，用户两个密码都还在手上，属于「麻烦一点」而不是「锁死」。真要根治得先有密钥世代的概念（1.5.33 才开始有）。
- 用户自己扔进备份目录、名字认不出来的文件不会出现在清单里。

## English summary

The "restore from this backup" button only ever appeared for backups tagged `pre-restore`, which are written only after you have already restored once — so a fresh install with several complete vault copies in `backups/` showed no restore entry at all. The candidate list is now every complete vault copy on disk (event backups, `bak.<date>`, `last.bak`, and each file under `old-key/<batch>/`), each row showing time, which step it was taken before/after, and whether the old password is needed.
