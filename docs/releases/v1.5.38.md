# PasswordMS 1.5.38

这一版没有新功能，改的全是「界面上的话怎么说」：四处成功提示和两格恢复提示。
主线只有一条——界面上的每句话，要么把发生的事说清楚，要么老实承认"我们不知道"，
不许用一句万能的「确定」敷衍，也不许把没看进去的东西说成"里面有什么"。

## 成功提示不再是一句「确定」

附件面板和设置页里有四处操作成功后的提示，原来用的都是「确定」两个字。
「确定」是**按钮上的字**——用户刚做完一件事，正想知道"做成了没有、做成了什么"，
回他一句「确定」，等于什么也没说。这个写法是被复制出来的：一个模块这么写了，
后面三个模块照抄，四代界面一直带着它。

现在四条提示各说各的结果，四门语言同步：

- 加入附件 →「附件已加入。」
- 导出附件 →「附件已导出到你选的位置。」
- 移除附件 →「附件已移除，内容会在同步后删除。」
- 设置里导出备份 →「备份已保存。请确认目标文件确实存在，且大小不是 0 B。」

最后一条特意把核对的方法写进提示里：导出写的是你选的位置，字节数程序会回读校验，
但"文件确实躺在哪"只有你自己看得见——0 字节的文件等于没导出来。

## 打不开的备份文件夹，不再断言里面有什么

恢复前的检查看到打不开的备份文件夹时，会提示"这些文件夹里有旧密码还能打开的备份，
需要你手动处理"。问题在于：打不开就是打不开，我们**连文件夹都没看进去**，
凭什么说"里面有"？中文和繁体的原文案把话说满了，英文和泰文却留着余地——
同一句话，两种语言下了两种结论，而所有测试全绿，因为没有任何一条测试读中文。

现在四门语言统一成「里面**可能**有旧**主**密码还能打开的备份」。两处改动各有讲究：
把"有"降级成"可能有"，是因为没看进去的东西只能猜测；把"旧密码"点名成"旧**主**密码"，
是因为本版本换主密码只换锁不换钥匙——写"旧密码"会让用户以为数据钥匙也换了，
从而放弃一份其实还能打开的备份。这两处现在都有绊线守着：文案改回断言式、
或者"主密码"退化成"密码"，测试立刻变红。

## 其余改动

其余都是不直接影响界面的话：走查单的每一句引文现在有脚本自动核对
（引号里的字必须真在字典里，"查不到"零容忍）；成功提示的守门测试升级成全仓扫描，
换一种写法借用按钮词也逃不掉。这些不改变任何功能，但让下一版更不容易把话写错。

## 已知限制

- 沿用上一版：Android 上的导出走系统文件选择器，写的是系统给的句柄，
  靠写完回读长度校验兜底（0 字节一律判失败）。
- 「可能有旧主密码还能打开的备份」只提醒，不代劳：哪些文件夹真的能打开，
  仍需要用户拿到旧主密码后自己逐个试。程序不猜、也不替你删。

## English summary

This release contains no new features; it fixes how the interface talks.

- **Success toasts no longer say just "OK".** Four success messages (attachment added,
  attachment exported, attachment removed, backup exported from Settings) used to show
  the button label "确定" (OK), which tells the user nothing about what just happened.
  Each now states the outcome in plain words, in all four supported languages. The
  backup-export message also reminds the user to confirm the file exists and is not 0 bytes.
- **Unreadable backup folders are no longer described with false certainty.** The
  pre-restore notice used to assert, in Chinese and Traditional Chinese, that those folders
  "hold backups openable with the old password" — but the folders could not be read at all.
  All four languages now say the folders *may* hold backups openable with the old **master**
  password, and name it explicitly: changing the master password changes the lock, not the
  key, so "old password" would mislead users into abandoning backups that still open.
- Everything else is internal quality work: an automated checker now verifies that every
  quoted phrase in the manual test checklist actually exists in the dictionaries, and the
  toast guard was upgraded to a repository-wide scan.

Known limitations carry over from the previous release; see the Chinese section above.
