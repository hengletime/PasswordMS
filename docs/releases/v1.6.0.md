# PasswordMS 1.6.0

1.6 的第一版先修手机上两处看着别扭的地方：一句话把手机说成了电脑，一张表被挤成了一字一行。

## 「本机自动备份」不再说自己是「这台电脑」

手机上打开设置里的自动备份，描述写的是「先把整个库复制一份放在**这台电脑**上」。
可手机上没有电脑——备份就在这台手机里，卸载就一起没。这句话会让人以为东西存在别处，
从而高估自己的安全余量。

原因不是漏改了某个平台：Windows 与 Android **共用同一套字典**，同一句话两端原样显示，
这层压根没有按平台分叉的机制。有意思的是这张卡片的分区标题本来就叫「本机自动备份」，
只有描述里写着「这台电脑」——自己跟自己不一致。

现在五句话统一改用「本机」：卡片描述、警示句、删除失败提示、删旧备份的确认框、
改密码后的说明。取舍是**不加平台变体**——为一个词维护四语言二十个新键不值当，
而且「本机」在电脑和手机上都读得通，本来就是中文软件里的中性说法。

加了一条守门断言钉住这件事：五句话在四种语言里都不得出现「电脑」或「電腦」，
同时**必须**正面写出「本机 / 本機」——只检查「没有错词」是能被「整句删空」绕过的。

## 备份记录不再被挤成一字一行

展开「查看全部备份」后，表格有三列：时间、这是哪一步、操作。时间列和操作列都是不许
换行的（一个日期、三个按钮），390px 宽的手机上这两列就吃掉约 265px，中间那列只剩
几十像素——中文被压成一字一行：「上 / 一 / 次 / 改 / 动 / 之 / 前 / 的 / 备 / 份」
竖着排下来，整张表被撑到半屏高。

手机上改成**每条两行**：上面一行是「时间 ……… 退回去 📌 删除」，下面一整行放
「这是哪一步」的描述。桌面一行没动，还是三列表格。

改法是只调整布局方式、**不动页面结构**，所以桌面端的表格语义、屏幕阅读器读到的
单元格顺序都没有变化。这里踩到一个陷阱值得记下来：表格外层和表体必须一起改，
否则浏览器会按表格规则把它修回原样——样式看着写了，效果是零。这条已经写成断言，
谁改漏一半就会立刻被测试拦下。

## 已知限制

- **浏览器地址栏里打网址**（`Ctrl+4`）仍未确认修好。已排除按键、权限、注入通道三种原因，
  1.5.41 做的是放慢输入节奏（按「地址栏会自动补全并选中一截」这个最可能原因），
  属于缓解不是确诊。若仍打不出来，日志里有一行「文本段注入完成」——有它就是
  事件发出去了、被对方吞掉；没有就是注入通道本身的问题，可以据此分诊。
- 目标程序以管理员权限运行时，**普通权限的 PasswordMS 无法代填**（Windows 的限制）。
  界面会明确提示并以红字告知，不会假装成功。
- 备份记录的窄屏布局只作用在 768px 以下。桌面和平板上仍是三列表格——那里宽度够，
  强行堆叠反而让一屏看到的条数变少。

## English summary

Version 1.6 starts by fixing two rough edges on phones.

**The automatic-backup section no longer calls the phone a computer.** On Android the
description read "copy the whole vault onto *this computer*", but there is no computer —
the backups live on that very phone and disappear when the app is uninstalled. The wording
made the phone look safer than it is. The root cause was not a missed platform branch:
Windows and Android share one dictionary and this layer has no per-platform wording at
all. The section title was already "Automatic backups on this device", so only the body
text disagreed with it. Five sentences now use the neutral term "本机" (this machine);
no per-platform variants were added, because maintaining twenty new keys across four
languages for one word is not worth it, and the neutral term reads correctly on both
platforms. A guard test now forbids the words for "computer" in these five sentences in
both Chinese variants, and also requires the positive wording — checking only for the
absence of a wrong word can be defeated by deleting the sentence.

**The backup table no longer collapses into one character per line.** The table has three
columns: time, what happened, and actions. The time and action columns may not wrap (a
date, three buttons), so on a 390px phone they consume about 265px and leave the middle
column a few dozen pixels wide — Chinese text then wrapped one character per line and
pushed the table to half a screen tall. On narrow screens each record is now two rows:
time and the three actions on the first, the description spanning the full width on the
second. The desktop table is unchanged. Only layout is adjusted, never the markup, so the
table semantics and the cell order read by screen readers stay identical. One trap worth
recording: the table element and its body must both be detached from table layout, or the
browser restores it and the new styles silently do nothing — that is now an assertion, so
a half-done edit fails the tests immediately.

**Known limitation:** typing a URL into a browser's address bar (`Ctrl+4`) is still not
confirmed fixed. Key handling, permissions and the injection channel have been ruled out;
version 1.5.41 slowed the typing down based on the most likely cause (address bars
autocomplete inline and select the completion). That is a mitigation, not a diagnosed fix.
The new "text segment injected" log line distinguishes "events were sent but swallowed"
from "the injection channel failed".
