# PasswordMS 1.6.5

这一版只做了一件你能看见的事：**两颗热键撞成同一个组合时，提示终于说的是实情**，而不是把你支去查一个根本不存在的"其它程序"。

## 「该热键已被其它程序占用」——占用它的是本程序自己

现象：在设置里把「自动输入快捷键」录成和「全局热键」相同的组合，保存后提示
「该热键已被其它程序占用，请换一个组合」；换成别的组合也照样报，甚至越改越乱。

真相：Windows 里同一个组合只允许注册一次。第二颗热键注册时系统必然回「已被注册」，
我们把这句话原样译成了「被其它程序占用」。可占用它的就是本程序——你按着提示去改
**这一颗**，而真正该改的是**另一颗**，所以怎么换都好不了。

现在：录制时就拦下，并说清新的是什么问题——

> 这组键已经用在另一颗热键上了。两颗热键不能用同一个组合，请换一个。

拦在注册之前，所以你原来的两颗键**照常生效**，配置也不会被写坏。简体中文、繁体中文、
英文、泰文四套文案都补了这句。

还留了一条兜底：如果你手动改过配置文件、留下两颗相同的键，程序启动时只装主键、把重复的
那一颗跳过并写一行日志——一个坏配置不该让唯一能把窗口唤回来的键一起失效。

## 顺手订正了一批过期的说明

这些在界面上看不到，是给走查的人和以后改代码的人看的：自动输入的注入节奏改成实测的
12 / 50 / 300 / 150 毫秒（原来写的 6 / 50 / 200 是旧值），自动输入的发布版本订正为
1.5.41 起，附件路径的报错口径改成与 1.6.4 的实际行为一致，「目标程序以管理员权限运行」
那条的期望文案与判据换成现在真正会显示的那句，走查单新增一条「两颗热键不能录成同一个」。

## 已知限制

- 「两颗热键相同」这句提示在真机上有个前提：**另一颗键当前没有注册成功**（比如被别的
  程序占着、设置页标红）时最容易触发。如果那颗键正生效，按下它会被系统先拦走，你会先
  看到 8 秒后那句「按了没反应？这个组合已经被注册成全局热键了……」——这条老路径的行为
  本版没有改动。
- 与 1.6.3 及更早版本混用做同步时，旧版发来的裸中止帧一律显示「同步已中止」（这是 1.6.4
  起的既有约定，本版没有改）。
- 两个平台都只在打包机上核过产物完整性与版本号，**还没有在真机上走一遍**：走查单
  7.1–7.9、3.86、3.87 仍待走查。

## English summary

This release fixes one user-visible problem: when you tried to record the same key combination
for both the quick-search hotkey and the auto-type hotkey, the app said "that hotkey is already
taken by another program" — but the program holding it was PasswordMS itself. The second
registration can never succeed, and the message sent you to fix the wrong one of the two hotkeys.
The combination is now rejected before registration with a truthful message ("that combination is
already used by your other hotkey"), both keys keep working, and the saved settings are left
untouched. A duplicate pair left in a hand-edited config no longer disables the main hotkey at
startup. A batch of outdated internal notes (auto-type injection timing, the version auto-type
shipped in, attachment error wording, and three walkthrough criteria) was corrected. Product
artifacts were verified on the build machine only; on-device walkthroughs are still pending.
