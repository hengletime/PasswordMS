# PasswordMS 1.5.33

这一版修一个「分组全反」的老问题，并把 1.5.32 留下的两个半截功能接完。

## 分组全反的根子

备份分成两组：**用现在的密码能打开** / **改密码之前的**。以前这个归属只看文件在哪个目录——换密码时程序把上一代备份搬到 `old-key/` 下面，看目录就知道该归哪组。

问题是**恢复**。恢复是把一份备份整库复制过来，目录位置原样不动。如果你的库是从旧密码那一代恢复出来的，那么整库都属于「旧密码」这一代，可这些文件却在正常目录里——分组于是全反：该进「旧密码」的进了「现在这把」，反过来也一样。用户看见的是一堆错误的标签，按标签输密码当然打不开。

现在每份备份自己带一个**密钥世代号**，写在自己的文件头里。归属按号码比，不再看目录：同一代就是一组。目录位置降级成兜底——只在文件里没有号码时（1.5.32 及更早拍的备份）才用，并接受它可能不准。

## 措辞改清楚了

「旧密码那组」的标题和恢复时的提示，四个语言都重写了。原来的说法要求用户理解「归档」「上一代」这类内部概念；现在只说一件事：**这一组里的备份，要用你改密码之前那把密码才能打开。**

## 钉住与自动清理接完

1.5.32 的界面里有「钉住」和「自动清理」开关，但只到界面为止。这一版把两端接通：

- 点图钉 → 这份备份不会被自动清理删掉，你自己随时能删；
- 钉住不占保留名额——钉几份都不会让更早的更容易被删掉；
- 自动清理开关关掉之后，一份都不会自动删；
- 删掉最后一个备份点时，立刻回收已经失效的钉住记录，不留悬挂条目。

## 已知限制

- **1.5.32 及更早拍的备份没有世代号**，只能按目录位置判。也就是说：用这些老备份恢复之后，分组仍可能全反。这一条在 1.5.34 用「比头部校验值」补掉了。
- Android 端覆盖安装即可，不需要卸载重装。

## English summary

Backups now carry a key-generation number in their header, so the "which password opens this" label no longer depends on folder location — which is always wrong right after a restore. Folder position is kept only as a fallback for backups made before 1.5.32. Wording for the old-password group and restore prompts was rewritten in all four languages, and the pin / auto-cleanup switches (present in 1.5.32's UI) are now wired end to end.
