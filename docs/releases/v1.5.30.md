# PasswordMS 1.5.30

这一版修一个会留下「未知分组」的同步问题，另外把四道门禁补成真的能拦住人的样子。

## 删掉的分组，条目还记着它

多台设备同步时，如果一台删了某个分组，另一台收到的只是「这个分组没了」。程序照做——把分组本身删掉——但**它下面的条目还记着那个已经不存在的分组**。界面读不出分组名，就显示成「未知分组」，条目看着像丢了，其实还在。

本地删除这条路本来是逐条搬出去的，只有同步这条路漏了。现在三层一起收口，而且只用一个判据：**分组不存在，就等于未分组**，与仓库里其它地方同一口径。

两个细节没有让步：

- **要推进 `rev`，但不能动 `updated_at`。** 不推 `rev`，对端每轮都会报「同一个版本号、不同内容」的冲突，而且改完也发不出去；动了 `updated_at`，就等于把「换了个位置」伪装成「被编辑过」——排序和「最近修改」全乱。
- **回收站里的快照不修。** 那是「删除那一刻长什么样」的凭据，还原时由还原逻辑逐条修正，不该在同步里被偷偷改写。

## 危险提示不再静默消失

设置页有两格提示（有几份备份删不掉、目录读不出来）。它们原来挂在一个条件分支的兄弟位置上，改一处条件就可能让整格提示**悄无声息地不出现**——测试全绿，用户什么也看不到。

现在收成一个函数，判据写成一句能检查的话：**只有明确的 0 才允许沉默**。`null`、负数、数不出来，一律开口说话，并且不编造数字（数不清就直说数不清）。

## 门禁补成能拦人的

- **体积门原来验错了对象**：Android 那侧扫的是构建中间目录，那里只有未签名的半成品——真正的安装包不在范围内，中间产物在就算「找到产物」，拿错文件也报绿。现在两侧都按当前版本号收窄，只核验真正要发出去的那几件。
- **新增版本同步门**：版本号是四处不是三处，漏一处会让干净检出 `cargo build --locked` 直接失败。这门逐处打印并跑一次 `cargo metadata --locked --offline`——光比字符串比不出锁文件会不会炸。
- **总门首尾各拍一次快照**：跑的过程中 HEAD 或工作区变了，读数就作废，不许拿着半路变过的树报绿。

## 已知限制

- 如果一次分组删除被分页切成两批，第一批先收口，那些条目可能先进冲突箱——多一次仲裁，不丢数据。要彻底消除得改冲突判定口径，本版没动。
- 快照自检只比对文件集合与 HEAD，**文档内容的改动它看不见**。本轮实测期间确实改过设计文档，已如实登记；要堵这个洞得把快照扩到内容哈希。

## English summary

Fixes a sync bug that left items pointing at a deleted folder (they showed up as "unknown folder"): deleting a folder now notifies its items on every path, with a single rule — no folder means unfiled. Also hardened four gates: the size check now validates the real installers instead of unsigned build intermediates, a new version-sync gate catches the fourth version location, and the gate run now snapshots HEAD plus the working tree before and after so mid-run edits invalidate the numbers.
