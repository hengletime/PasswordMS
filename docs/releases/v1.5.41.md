# PasswordMS 1.5.41

这一版把「按热键、选条目、自动填进别人的窗口」这条路上最容易踩空的四件事修掉了：
按键记不住、管理员窗口里没反应、网址打不进浏览器地址栏、钉住的条目不在最前面。

## 按键改成 Ctrl + 数字，跟 KeePassXC 一样

以前用 `Alt` 组合键，Windows 上不可靠——`Alt` 会先被系统菜单和输入法吃掉，事件根本到不了
弹窗，所以「`Alt` 网址」按了没反应是必然的，不是偶发。

现在键位与 KeePassXC 一致，顺序也照抄，不按「顺手程度」重排（肌肉记忆比顺手重要）：

| 按键 | 打出的内容 |
|---|---|
| `Enter` | 用户名 + 密码（完整序列，带回车） |
| `Ctrl+1` | 只有用户名 |
| `Ctrl+2` | 只有密码 |
| `Ctrl+3` | 动态口令（6 位验证码） |
| `Ctrl+4` | 只有网址 |

键位映射抽成独立函数并配了单测，还加了一条守门断言：弹窗组件里**不许**出现任何修饰键
判断。上一版这段逻辑写在组件内部、没有测试，所以「真机按不出来」在交付前没人知道——
代码看着完全正确。

## 管理员权限的窗口里，现在会说清为什么打不进去

在管理员权限的程序（管理员 PowerShell、任务管理器）里按热键选条目，以前是「按了什么也
没发生，也没提示」。原因不体面：Windows 的权限隔离（UIPI）会直接丢弃来自低权限进程的
按键事件，而系统调用的返回值仍然报「成功」——程序从结果上根本看不出失败，所以连失败
日志都没有。

现在改成**动手之前先问一句**：目标程序是不是以管理员权限运行、自己是不是。是的话立刻
在弹窗上写明「目标程序以管理员权限运行，普通权限注入不进去」，而不是打完了什么也没发生。
这条提示一定要在弹窗收起来**之前**出现——收起来之后，对方的权限比我们高，普通进程抢不回
前台，提示写了也没人看得见。

## 钉住的条目和手动排的顺序，现在真的在浮层最前面

后台本来就把顺序排好了：钉住的一块（按你拖出来的顺序）在最前，未钉住的按使用频度往下排。
问题出在弹窗这一层——它自己又排了一遍，用的是「匹配得分 → 使用次数 → 标题」，**排序里
根本没有「钉住」这一项**。刚呼出时还在空查询状态，得分全是 0，于是整体退化成「按使用
次数降序」，把你刚钉上去、但用得还少的那几条冲到了下面。

现在弹窗只管「搜索时谁更匹配」这一件事，其余顺序一律照后台给的来。同分时保持原有先后，
等于免费继承了「钉住 → 手动顺序 → 频度 → 最近使用 → 最近更新」这五层。后台哪天调整排序
规则，弹窗自动跟着变，不会再长出第二套事实。

## 已知限制

- **浏览器地址栏里打网址**（`Ctrl+4`）仍未确认修好。已排除按键、权限、注入通道三种原因，
  现在做的是放慢节奏（等焦点稳定、字符间隔加倍、每段文本前留静默期）——这是按最可能的
  原因（浏览器地址栏会自动补全并选中一截，太快的后续字符会把选中内容替换掉）做的调整，
  不是确诊修复。若仍打不出来，日志里有一行「文本段注入完成」，有它就是事件发出去了、对方
  吞了，没有就是注入通道本身的问题，可以直接据此分诊。
- 目标程序以管理员权限运行时，**普通权限的 PasswordMS 无法代填**（Windows 的限制，无解）。
  要么以同样的管理员权限运行本程序，要么手工复制粘贴。界面会明确提示，不会假装成功。
- `Ctrl+5`（KeePassXC 的虚拟键盘）与 `Ctrl+Shift+1..4`（复制到剪贴板）**刻意不做**：前者
  没有安全桌面键盘做支撑，后者是快速搜索小窗的职责，两处重复只会让「按哪个键」变成新的
  记忆负担。
- 钉住条目在浮层里的位置依赖后台返回的顺序，弹窗不做二次排序。这是有意的设计取舍——单一
  事实来源比前端多一层兜底更不容易错。

## English summary

This release fixes four things on the "press the hotkey, pick an item, have it typed into
another window" path.

**Key bindings moved to Ctrl + digits, matching KeePassXC** (order copied verbatim, not
reordered for convenience): `Enter` types username + password, `Ctrl+1` username only,
`Ctrl+2` password only, `Ctrl+3` the 6-digit TOTP code, `Ctrl+4` the URL. The old `Alt`
combinations were unreliable on Windows — `Alt` is consumed by the system menu and IME
before it ever reaches the app, so "`Alt` for URL" simply never fired. The mapping now
lives in its own tested function, and a guard test forbids any modifier-key handling
inside the picker component: last time this logic sat inline with no tests, so "the key
does nothing on a real machine" was invisible before delivery.

**Elevated target windows now say why auto-type cannot work.** When the target app runs
as administrator, Windows UIPI silently discards synthetic keystrokes from a lower-integrity
process while the API still reports success — the old code therefore had no failure to
report and showed nothing at all. The app now checks the target's elevation *before*
injecting and shows an explicit message in the still-visible picker. The check must happen
before the picker is hidden: once hidden, a normal-privilege process cannot reclaim the
foreground from a higher-privilege window, so any message written afterwards would never
be seen.

**Pinned items and manual pin order now actually appear first in the picker.** The backend
already returned the right order (pinned block by `pin_order`, then unpinned by usage
frequency), but the picker re-sorted everything with "match score → use count → title",
which had no notion of pinning at all. With an empty query every score was 0, so the sort
degenerated into pure "most used" and pushed freshly pinned-but-rarely-used items to the
bottom. The picker now only decides relevance while searching; every other dimension is
inherited from the backend order. Stable sorting on ties yields "pinned → manual order →
frequency → last used → last updated" for free, and follows any future backend change
without growing a second source of truth.

**Known limitation:** typing a URL into a browser's address bar (`Ctrl+4`) is still not
confirmed fixed. Key handling, permissions and the injection channel have been ruled out;
the current change slows the typing down (longer focus settle, doubled per-character delay,
a quiet period before each text segment) based on the most likely cause — address bars
autocomplete inline and select the completion, so characters that arrive too fast replace
it. This is a mitigation, not a diagnosed fix. A new log line ("text segment injected")
distinguishes "events were sent but swallowed by the target" from "the injection channel
itself failed".
