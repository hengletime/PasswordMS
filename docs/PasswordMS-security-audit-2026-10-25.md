# PasswordMS 本地密码管理工具安全审计报告

- **审计日期：** 2026-10-25
- **审计对象：** PasswordMS 本地密码管理工具源码
- **技术栈：** Rust 核心库、Tauri 2、Svelte 5
- **整体风险评级：** 中
- **审计方式：** 静态源码审计、前端依赖漏洞数据库核对
- **审计边界：** 未进行动态渗透、崩溃断电测试或移动端实机验证；未修改任何源码

## 一、整体审计综述

核心密码学设计总体稳健：主密码不直接落地，账号、密码、备注及附件内容均位于加密记录中；未发现弱密码哈希、硬编码主密钥、直接绕过解锁读取密码库，或把账号密码写入日志的情况。

主要风险集中在：**同步身份私钥明文保存、解锁后的明文内存生命周期、文件权限依赖系统配置、导入与同步缺少资源上限、容器截断及非事务写入的数据完整性，以及开发测试依赖的已知漏洞。**

目前未发现足以将整体评级直接提升为“高”的已核实远程凭据泄露或解锁绕过漏洞。

本报告严格区分：

- **安全漏洞：** 已确认可能造成敏感信息暴露、资源消耗、数据完整性受损或业务安全语义失效的问题。
- **编码隐患：** 依赖运行环境、异常时序或使用方式才能显现的安全与可靠性风险。
- **建议优化点：** 仅表示需要进一步确认或关注，不作为已确认漏洞。

### 核查通过的部分

- 新建库时使用随机主库密钥，主密码用于派生 KEK，不直接作为库密钥保存。`Session::create` 位于 `crates/passwordms-core/src/session.rs:89-120`。
- 账号、密码、备注和附件正文均在记录帧解密后才出现，未发现这些业务敏感字段以明文直接写入密码库。
- 容器头部中的盐、KDF 参数、包裹后的库密钥、校验值及计数属于元数据，其中包裹后的库密钥不是明文密钥。

## 三、加密原语与随机数

**本次未发现弱加密算法或不安全随机数问题。**

- `crates/passwordms-core/src/crypto/kdf.rs:15-49`：使用 Argon2id 和 HKDF-SHA256。
- `crates/passwordms-core/src/constants.rs:28-50`：默认 Argon2id 参数为 64 MiB、3 次迭代、并行度 1；盐长度 16 字节。
- `crates/passwordms-core/src/crypto/aead.rs:32-81`：使用 XChaCha20-Poly1305，nonce 为 24 字节，并带 Poly1305 完整性校验。
- 每条记录使用独立随机的记录密钥，记录密钥再由库密钥包裹；未发现“简单 AES 无 IV”或固定 nonce 的设计。
- 随机盐和密钥由操作系统随机源生成，未发现使用时间、固定常数或普通伪随机数生成密码学密钥。
- TOTP 中的 SHA1 用于标准 HMAC-SHA1 一次性密码算法，不属于使用 SHA1 存储主密码的问题。

## 四、内存安全

| 分类 | 风险等级 | 代码位置 | 问题描述 | 风险危害说明 |
|---|---|---|---|---|
| 编码隐患 | 中 | `crates/passwordms-core/src/store/repository.rs:191-209,275-335`；`src/lib/stores/vault.svelte.ts:11-14,42-50,270-279` | 解锁时整个库被解密并保存在 Rust 内存索引中，前端同时缓存条目数据。敏感字符串在解锁期间长期存在；锁定时 Rust 侧有擦除逻辑，但普通 `String` 的历史副本、序列化及 IPC 缓冲区无法全部保证覆写。前端 `reset()` 主要清空引用，不能擦除 JavaScript 引擎中的旧字符串和垃圾回收前副本。 | 内存转储、崩溃转储或进程内存读取可能暴露敏感内容。 |

## 六、密钥管理

- **未发现主密钥、盐或加密种子硬编码在源码中。**
- 盐、库密钥和记录密钥均在运行时随机生成。
- 同步设备使用的库密钥以包裹形式保存，不是直接明文保存。
- 已确认的密钥管理问题是第二章中的 **Host 长期身份私钥明文文件**，不应与“密码库主密钥明文保存”混同。

## 八、访问控制与解锁校验

**本次未发现可绕过解锁直接读取密码库的路径。**

- 条目、分组、附件和同步变更等敏感操作基本通过 `session.repo()` 或 `session.repo_mut()` 获取仓储；锁定状态会返回未解锁错误。
- 解锁先派生密钥，再验证校验值并解包库密钥，失败统一映射为解锁失败。
- 对损坏头部与错误密码路径进行了错误码和耗时统一处理，未发现简单的错误信息解锁绕过。
- `import_preview` 不要求解锁，但其解析对象是用户主动选择的外部导入文件，并非当前密码库，因此不构成本次已确认的密码库越权读取。
- `sync_accept_pair` 虽存在占位实现，但实际配对流程另有令牌、ECDH 和确认校验，不能仅据该占位函数认定存在配对认证绕过。

## 十二、风险汇总

| 风险类别 | 主要结论 |
|---|---|
| 敏感信息存储 | 密码库业务内容已加密；Host 长期身份私钥明文保存；删除后旧密文存在残留。 |
| 加密原语 | 未发现弱密码哈希、固定 nonce 或不安全随机数。 |
| 内存安全 | Rust 和前端均存在解锁期明文缓存，无法保证所有副本被擦除。 |
| 输入安全 | 主要风险为导入、同步和 KDF 参数的资源边界不足。 |

| 日志与输出 | 未发现密码库敏感值直接写入日志；剪贴板清空存在失败窗口。 |

## 十三、仍需使用者自行确认的事项

1. 实际安装目录、便携目录及备份目录的系统 ACL，尤其是 `passwordms.identity` 的可读主体。
2. Android 发布构建的备份策略、最近任务缩略图和截屏行为。
3. 各平台在应用退出、挂起及剪贴板同步场景下的实际保留行为。
4. Rust 依赖的公开漏洞数据库扫描结果。
5. 异常退出、断电、文件截断及磁盘写失败情况下的数据完整性表现。
6. 崩溃转储、交换文件和系统内存转储是否可能包含解锁后的敏感数据。

---

**报告结论：** PasswordMS 的核心加密与解锁边界未发现明显高危缺陷，整体评级为中风险。现阶段最明确的安全问题集中在身份私钥持久化、明文内存生命周期、资源边界、文件权限及数据完整性；依赖扫描结论仅覆盖本次已执行的前端漏洞数据库检查，不代表全部第三方组件均无已知风险。
