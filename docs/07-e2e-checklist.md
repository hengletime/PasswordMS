# 真机 E2E 回归走查清单（#530-W3）

> **用途**：桌面（Windows）+ Android（V3 签名包）双端人工走查单。与 `07-quality-gate.md`（自动门禁）互补：门禁管机器可判的硬指标，本清单管「必须真人操作才能验证」的交互/环境路径。
>
> **执行规则**：每行完成后在对应端勾选 `[x]`；任一行不符期望 → 停止后续依赖项，登记缺陷（产品缺陷号 D-nn）并在「备注」列写复现步骤。走查完成后回填本文件并更新 03b §7 状态表。
>
> ⚠️ **`[X]` 不构成证据**：它只证明"当时有人走过这一行"，不证明"现在的界面还这么说"。2026-11-04 的实测就是这个下场——两条 `[X]` 行的期望文案早就漂了（1.2 / 1.4），清单看上去全绿。所以有一条硬规矩：**改 UI 文案的提交，必须同批核对该文案涉及的所有走查行**（成本就是跑一次 `node scripts/check-e2e-quotes.mjs`）。引文变了说明文案变了；反过来说，文案变了就该有人来看引文。
>
> ⚠️ **书写规范**：**原文引用用 `「」`（会被工具查），含义不加引号（不被查）**。这条不是格式洁癖——工具只扫 `「」` 里的片段，所以它决定了"哪句会被校验、哪句不会"。写含义的时候加引号，等于给工具塞一条必然查不到的引文。工具**只报警不判负、不进 `gate-all.sh`**（产品定：它衡量的是文档新旧，不是代码对错；若要进门只做增量告警）。
>
> **需求点编号约定**：F-nn = PRD 功能项；A-nn = 安全需求项；D-nn = 缺陷修复单；B-nn = 代码与文档中沿用的一套改进项编号（全仓 `B-03` 统一指「v1.5.29 自动回滚点」，`grep -rn "B-03"` 可核对）；§n.n = 架构/设计文档章节。
