## 2. 冲突裁决：#15 到底能不能关单

两位成员结论相反，主理人不能和稀泥，裁决如下：

| | 排障手 | 安全官 |
|---|---|---|
| 结论 | 已完成可关 | 不能关 |
| 依据 | 8 个 `file:line` 坐标 + 21 条守门测试通过 | M4 失败出口漏擦（静态事实）+ S8 两键相同未做 |

**裁决：采信安全官，#15 保持 pending。** 三条理由：

1. **主理人已独立复核源码事实**：`src-tauri/src/commands/autotype_cmd.rs:584` 是 `let mut buf: Vec<u8> = text.encode_utf16().flat_map(u16::to_le_bytes).collect();`，`:591` 的 `send_unicode(...)?` 排在 `:595` 的 `securemem::wipe(&mut buf)` **之前**；`buf` 装的是当前 Token 整段明文（`{PASSWORD}` 时就是整串密码），而 `crates/passwordms-core/src/securemem.rs:17` 明明定义了 `SecretBytes = Zeroizing<Vec<u8>>`，这里没用。`securemem.rs:3-4` 的纪律原文是「不得依赖作用域结束即回收」。这是类型 + 语句顺序的静态事实，不依赖真机。
2. **两份结论的分叉有解释**：现有守门 `autotype-guard.test.ts:412-443` 的「早退绊线」是用 `rustFnBody(cmd, 'pub async fn auto_type_fill(')` / `'pub fn autotype_candidates(')` 按函数头切函数体的，取不到 `:438` 之后独立的 `fn windows_inject`。排障手验的是「擦除**存在**」，没验「所有离开该缓冲的路径**都**擦了」——**存在性断言不能代替全称断言**，这是方法上的错，不是看漏了一行。
3. **排障手已主动撤回原判断**，改判「#15 仍然有效」，并独立复算了同样的 `:584/591/595` 与 `securemem.rs:17`。三方结论收敛为一致：**#15 保持 pending**。
4. **放行阻塞一列由主理人签**：M4 残留 = P0 / 安全影响未完全消除；S8 = P1 / 安全影响无（仅文案误导）。**不签放行。**

### 补强：7.9 前端落点已查清（2026-11-06 晚 · 排障手只读复核，修正 §3 第 2 行与行动清单 #3）

## 6.1 追加裁决：中止帧加固路线（#21 只读核对结论，2026-11-06 晚）

**锚**：`HEAD f30b9fe` / tree `03105f7e`；安全官全程只读，未改文件、未跑 cargo；所读 11 个路径 `git status --short -- ...` 为空。

- 中止帧是 `transport.rs:44-66` 的 `u32 LE 长度 + 帧体` **裸 TCP 帧**；`resync.rs:905-911` 的 `send_reject` 直连 `send_frame`、无 `seal_envelope`；`paging.rs:174/:218` 在信封解析失败时把原始 `Vec<u8>` 喂给 `parse_reject`（`protocol.rs:356-361` 签名里没有密钥），且在 `replay.accept` / `open_envelope` 之前返回 → 未认证入站分支成立。

**加固形状（两方案共用）**：保留 `{"t":"reject","code":…}` 形状，追加 `v/sid/seq/ts/nonce/mac` 可选字段（全 `#[serde(default, skip_serializing_if = "Option::is_none")]`）。**密码学裁定已由 audit-crypto 签（2026-11-06）：不签「同一把 `sync_key` 兼做 AEAD 与 HMAC」**——`sync_key` 已在做双职（`handshake.rs:174` VK 信封 AEAD + `derive_session_sk` 的 IKM），再叠 HMAC 就只剩标签区分一道防线；改用 HKDF 派生独立子密钥 `abort_key`（仿 `handshake.rs:109-124`，新增 `HKDF_INFO_SYNC_ABORT`），每次连接两次 HMAC 的成本可忽略。MAC = `HMAC-SHA256(abort_key, ABORT_LABEL ‖ 长度前缀(sid,seq,ts,nonce,code,sender_id,receiver_id))`，其中 `code` 必须走**长度前缀 + UTF-8 原字节**、**禁止把 JSON 片段进 MAC**，`receiver_id`（接收方自己的 id）也要进 MAC，把抗反射从「纪律」变成「结构」。IKM 仍取已传入 `recv_push_pages`/`recv_done` 的第一个参数 `sync_key`，派生在协议层内完成，接收侧零新增密钥**分发**管线。
接收侧 `paging.rs:174/:218` 单点验，**顺序由 crypto 硬约束钉死（先验 MAC、再基于 code/ts 产生行为）**：① serde 形状解析 + 字段完整性/长度闸（`mac` 32B、`nonce` 16B、`sync_key.len() == KEY_LEN`）——纯解析、不产生行为；② 用**本地** `session_id` / `sender_id` / `receiver_id` 重算 expected MAC；③ `handshake::verify_mac(&expected, &provided)`（长度不等即 false，截断天然被拒）；④ **验过之后**才 `replay.check_ts(ts, now)` 与 `reject_code_to_error(code)`；⑤ 任一步失败 → `CoreError::SyncAborted`，**绝不回显 raw code**、绝不落 `ERR_INTERNAL`。原「sid 单独常量时间比对」降级为诊断用途（方案 2 下 sid 是 MAC 输入，帧内不符自然导致 MAC 失败，不再并存两套认证闸）。**不要调 `replay.accept`**。
**IKM 钉死**：必须是 `paging::recv_push_pages`/`recv_done` 收到的那个 `sync_key: &[u8]`（resync 两端传 `&sk[..]`，配对通道传 `&self.keys.sync_key[..]` / `&keys.sync_key[..]`），**不是** `PreparedResync.sync_key: ItemKey`；取错会让配对通道两端算不出同一把 `abort_key`。**长度闸**：helper 入口先判 `sync_key.len() != KEY_LEN → CoreError::Crypto`，对齐 `aead.rs:16-18 cipher_for`（该坐标由 audit-crypto 复核）；HKDF 对任意长度 ikm 都成功，不会替你兜住误传空切片。`ABORT_LABEL` 保留作纵深但不再是主要域分离手段。
**方向与 id**：`AbortCtx` 带 `local_id` + `peer_id`，发送时 `sender_id=local_id, receiver_id=peer_id`，接收时重算用 `sender_id=peer_id, receiver_id=local_id`，方向写死，否则两端算出不同 MAC。`nonce` 若在明文帧里没被接收方实际使用，进 MAC 只是装饰，留着无害但不要再为它加语义。
